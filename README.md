## 記事の概要

 - AIにソフトを開発してもらう際にAIが要件をヒアリングして要件定義書を作成、要件定義書を元に設計書、設計書を元にコードを生成するという流れで開発を進めてもらうとすごく良い開発ができるよ
 - 世の中では設計ドリブンって言っているけど、要件書でよくない？
 - この記事では、要件定義書を元に設計書、コードを生成する流れを実際の例を交えて紹介するよ
   - claude_session_備品管理貸出管理アプリ.mdとclaude_session_CSVデータの分布比較アプリ.mdが例
 - AIに適当に作らせると、メンテができない。改良仕様としても壊し続けてしまうけど、要件定義書を元に作らせると、要件定義書を改良すればコードも改良されるから、メンテも改良もやりやすいよ
 - AIはサボってコードをプレースホルダとかにしてくることがあるけど、要件定義書を元に作らせると、要件定義書に書いてないことはコードにもしっかり書いてくれるから、サボりも減るよ
 - AIのサボり方とか勘違いの仕方が人間っぽいから、昔ながらのウォーターフォールでちゃんと「枠をはめて」開発してあげるとちゃんとしたソフトになるよ
 - githubのリポジトリに上記の要件定義書、設計書を作らせるためのプロンプトを公開しているよ
   - 要件定義用プロンプト: https://github.com/notfolder/roo_code_test/blob/main/agents/REQUREMENTS_DEFINITION_AGENT.md
   - 設計書用プロンプト： https://github.com/notfolder/roo_code_test/blob/main/agents/DESIGN_SPEC_AGENT.md
   - 実装のプロンプトはclaude codeがかなり良いコードを出してくれるから、要件定義書と設計書を渡して「この要件定義書と設計書を元にコードを書いて」って言うだけでかなり良いコードが出てくるよ
 - 30年の開発経験を元に要件定義、設計書の書き方をプロンプトにしているよ
   - AIと同じように専門家だけど勘違いしやすかったり、サボったりする人と中規模の開発を行うときのノウハウを活かしているよ
 - アジャイルも経験したけど、AIと開発するならウォーターフォールの方が合っていると思うよ
 　- ウォーターフォール開発でもAIなら1時間以内で要件定義書も設計書もコードもできるから、ウォーターフォールでもアジャイルに負けないスピードで開発できるよ
   - ちゃんと枠をはめてあげるとちゃんとしたソフトができるよ
   - 逆に枠をはめないで適当に作らせると、メンテも改良もできないコードができるよ
